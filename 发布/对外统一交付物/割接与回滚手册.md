# 割接与回滚手册（DUT 由 10.0.0.9 → 目标机）

前提：目标机已按《部署说明.md》完成部署，Web 界面可开。

## 一、割接

1. **停旧仿真**：10.0.0.9 上 `cd ~/hinggan/ems_simulate && docker compose stop`（mysql84 等其他容器不动）。
2. **备份 DUT 实时库**：
   ```
   cp /home/syth/QCzt2016/database/qplantagcrtdb.db /home/syth/QCzt2016/database/qplantagcrtdb.db.bak-$(date +%Y%m%d)-toTarget
   ```
3. **改 DUT PORT_NET**（sqlite3，`<目标机IP>` 用 set-site 打印的值，当前示例 10.0.0.7）：
   ```
   sqlite3 /home/syth/QCzt2016/database/qplantagcrtdb.db \
     "UPDATE PORT_NET SET remote_address='<目标机IP>' WHERE remote_address='10.0.0.9';"
   sqlite3 /home/syth/QCzt2016/database/qplantagcrtdb.db "SELECT * FROM PORT_NET;"
   ```
4. **重启 DUT**（顺序不可乱）：
   ```
   ps -ef | grep qplantagcserver        # 记下全部相关 pid
   kill <pid>                            # 若进程以 root 启动需 sudo -S kill
   # 静置 ≥80 秒（60s 偶发卡死 installTranslator，80s 实测稳）
   cd /home/syth/QCzt2016/build
   export DISPLAY=:0 XAUTHORITY=/home/syth/.Xauthority
   nohup ./qplantagcserver > ~/qserver.log 2>&1 < /dev/null &
   ```
   等初始化日志出现 `rtdbManager start`（偶有 1~2 分钟慢启动，勿过早判死）。
5. **验证**（三条全过即割接成功）：
   - 连接：DUT 上 `ss -tn | grep <目标机IP>` 应见 502、2404 两条 ESTAB；目标机上 `netstat -an | findstr <DUT_IP>` 应见一条到 DUT:2404。
   - 通道状态：`sqlite3 ...qplantagcrtdb.db "SELECT yx_num,yx_data FROM YX_DATA WHERE yx_num IN (101,102,107);"` 三个都应为 **65**。
   - 数据：目标机改一个遥测值（Web 或 write-baseline），40~60s 后 DUT 库 `YC_DATA` 对应行变化。

## 二、回滚

1. DUT：`UPDATE PORT_NET SET remote_address='10.0.0.9' WHERE remote_address='<目标机IP>';`（或直接用步骤 2 的备份覆盖实时库）。
2. 10.0.0.9：`cd ~/hinggan/ems_simulate && docker compose restart`，随后按既有恢复链（start×3 → 容器内 socket 实测 502/2404 → autoread/gi → 重写点值）。
3. DUT 重启（同割接步骤 4：kill → 静置 ≥80s → 拉起）。

## 三、日常运维速查（目标机）

| 场景 | 操作 |
|---|---|
| 重启仿真 | `scripts\stop.ps1` → `scripts\start.ps1 -NoMaster` → 重启 DUT（等到 `rtdbManager start`）→ `scripts\start-master.ps1`。`-NoMaster` 只起后端、不起主站-仿真，主站等 DUT 起来之后再起，**按这个顺序最稳妥**（见第四节第 2~4 步）。不带 `-NoMaster` 的 `scripts\start.ps1` 会立刻起主站，之后若再重启 DUT，就是 2026-11-28 崩溃过一次的顺序 |
| 改点值 | Web 界面或 `tools\ems_local.py write <plc\|ncs\|master> <大写点号> <值>` |
| 总召唤 | `tools\ems_local.py gi master`（主站收值靠总召） |
| 看 104/Modbus 报文 | `log\iec104.log`、`log\PLC-仿真\`、Web 界面报文页 |
| DUT 侧查询 | `sqlite3 /home/syth/QCzt2016/database/qplantagcrtdb.db "SELECT ... FROM YC_DATA WHERE yc_num=...;"` |
| 显示 / 隐藏「单位」列 | 改 `config.ini` 的 `[server] show_unit_column`（`true` / `false`），保存后刷新浏览器；仿真器和 DUT 都不用重启 |
| 改某个点的单位 | 用 SQL 改库里的 `point_yc.unit`（`tools\point-units-20261128.sql` 是全部 78 个点的单位），之后整进程重启并重启 DUT。**不要用"重新加载设备配置"**：它会停掉设备服务 |

## 四、同机换包升级（如 1.0.3 → 1.0.4）

下面的顺序用到 `start.ps1 -NoMaster` 和 `start-master.ps1`（2026-11-28 加入；包的 `scripts\` 里有 `start-master.ps1` 才算带）。没有这两个脚本的旧包照旧：直接起 exe，DUT 起来后跑 `tools\ems_local.py start master`、`autoread master`、`gi master`。

1. 备份旧包的库：`tools\sqlite3.exe "<旧包>\data\ems.db" ".backup '<旧包>\data\ems.db.bak-<日期>-<事由>'"`。
2. 旧包目录跑 `scripts\stop.ps1`，再在新包目录跑 **`scripts\start.ps1 -NoMaster`**：只起后端（PLC-仿真、NCS-仿真 随程序自动监听），**不起主站-仿真**，并打印下一步。新包自带基线库，旧包里在界面上改过的配置不会带过去。新包没有这个开关的，照旧直接起 exe（双击，或 PowerShell：`$env:EMS_ROOT_DIR='<新包目录>'; Start-Process -FilePath '<新包目录>\ems_simulate_backend.exe' -WorkingDirectory '<新包目录>'`）；**不要跑不带开关的 `start.ps1`**，它会立刻启动主站-仿真并开自动读取。
3. 重启 DUT（同第一节"割接"的步骤 4：kill → 静置 ≥80 秒 → 拉起），等到 DUT 自己的日志 `~/QCzt2016/build/logfile/<日期>/qplantagcserverlog.txt` 里出现 `rtdbManager start`（标准输出日志里没有这一行）。
4. 这时再起主站：在新包目录下跑 **`scripts\start-master.ps1`**。它启动 主站-仿真、开自动读取（batch，周期 2000 ms）、发总召唤，并确认 DUT 回了报文；起主站之前先探测 DUT，下面三种情况**不起主站**，只报错并给出补救办法：2404 端口连不上；端口接受了连接又马上断开（在这种对端上起主站，仿真器崩溃过）；DUT 的端口通、但 DUT 还没连上仿真器（PLC-仿真 上没有客户端连接，确认无碍可加 `-Force`）。然后核对第一节步骤 5 的三项验证。
   **按这个顺序走最稳妥。** 2026-11-28 升级到 1.0.4 时，先跑 `start.ps1`（主站随即起来并开自动读取）再重启 DUT 的那一次，仿真器在 DUT 连上来的瞬间崩溃了（`_c104.pyd` 访问违规）；改按上面的顺序后完成。因果没有严格证明，但先照这个顺序做。
5. 回滚：`scripts\stop.ps1` → 旧包目录下跑 `scripts\start.ps1 -NoMaster`（旧包没有这个开关就直接起它的 exe）→ 重启 DUT → 等到 `rtdbManager start` → 旧包目录下跑 `scripts\start-master.ps1`（没有就照旧 `tools\ems_local.py start master`、`autoread master`、`gi master`）。旧包自带它自己的库，不受新包影响。
