# 部署说明（Windows 原生版仿真器，解压即用）

适用包：`ems-sim-win-<版本>.zip`。被测端（DUT）为麒麟 VM 里的 qplantagc（默认 10.0.0.194）。

> **⚠ 目标机系统要求（2026-11-21 实测）：Windows 8.1 及以上，不支持 Windows 7。**
> 依据：在 Windows 7 x64 SP1 旗舰版实测，exe 启动即报"无法启动此程序，因为计算机中丢失 api-ms-win-core-path-l1-1-0.dll"——该 API 集为 Windows 8 引入，Python 3.9+（本包为 3.12）硬依赖，属官方支持矩阵的硬边界而非打包缺陷。如确需 Win7，须另建 Python 3.8 构建线并重验全部原生依赖（c104/pydantic 等），工作量另议。
> 包的其余环节（BITS 分发传输、解压、文件完整性）在同一台 Win7 上均验证通过。

## 5 步部署

1. **解压** zip 到任意本地目录（建议纯英文无空格路径，如 `D:\ems-sim`）。
2. **杀软放行**：把整个解压目录加入杀软信任/白名单（未签名的 PyInstaller exe 常被按位置拦截写文件——联想电脑管家实测会拦，症状是启动即退、日志报 PermissionError）。
3. **（可选）防火墙放行**：管理员 PowerShell 运行 `scripts\allow-ports.ps1`（放行入站 TCP 502/2404，源限 10.0.0.0/24）。若目标机防火墙公用配置档为关，可跳过。
4. **设定站点**：`scripts\set-site.ps1`（DUT 默认 10.0.0.194 可跳过；换 DUT IP 时带 `-DutIp x.x.x.x`）。脚本同时会打印 DUT 侧 `PORT_NET` 需要的修改 SQL。
5. **启动**：`scripts\start.ps1`——自动起后端、等健康检查、启动三台设备、开主站自动读取与总召唤。完成后浏览器开 `http://127.0.0.1:8991` 即 Web 界面。改基线点值可再跑 `scripts\write-baseline.ps1`（清单在脚本顶部，可编辑）。

随后按《割接与回滚手册.md》把 DUT 切到本机。

## 已知事项（都实测过，照做即可）

| 事项 | 说明 |
|---|---|
| 自动开浏览器 | 启动后健康检查一通过就用默认浏览器打开 `http://127.0.0.1:8991`（Windows 默认开启；config.ini `[server]` 加 `open_browser = false` 可关——**1.0.4 起才真正生效**，1.0.3 及以前改了无效，只是默认行为恰好符合预期） |
| 单例模式 | 同一运行根（exe 所在部署目录）只允许一个实例，重复启动会提示后自动退出（按运行根加锁，崩溃无残留锁；不同 EMS_ROOT_DIR+端口的并行调试实例不受影响） |
| 版本号 | 首页右下角显示版本（如 v1.0.0，来自包根 `version.txt`，由 make-package 按版本参数写入）；`/api/health` 的 version 字段同源 |
| 界面裁剪 | 上游页脚版权栏与设置页"联系作者"入口已隐藏（服务端注入 CSS + 前端菜单项剔除）；**前端重编译或 exe 重建后需重跑 `patch_contact.py` 剔除脚本**，否则"联系作者"菜单回归 |
| 点号大小写 | API/脚本调用测点必须用**库内大写**（`YC512`，不是 `yc512`）；运行时按内存字典精确匹配 |
| 设备"重启"不可用 | 设备级 stop→start 会假活（104 服务器停了起不来）；**重启一律整进程**：`scripts\stop.ps1` → `scripts\start.ps1 -NoMaster` → 重启 DUT → `scripts\start-master.ps1`（顺序见《割接与回滚手册》第三节"重启仿真"）。**也不要用"重新加载设备配置"**（`reload-config` 接口）：它会把设备换成未启动的状态，PLC-仿真、NCS-仿真随即停止监听，DUT 的两条连接随之中断 |
| 仿真停机后 DUT 要重启 | DUT 的 104 采集通道对不干净断线**不自愈**（卡 CLOSE-WAIT），仿真重启后必须按手册重启 DUT |
| 启动顺序 | 整进程重启后遥测基准值由程序启动时自动推送，不必手写；现行包下 DUT 跟随 NCS 每秒的周期上送，不依赖总召唤（早先"DUT 只认总召"的结论是 10.0.0.9 docker 版的观察）。`start.ps1` 已按正确顺序编排 |
| Web 远程访问 | `config.ini` 的 `host` 默认 `127.0.0.1`；要别的机器看 Web 改 `0.0.0.0` 后重启（**1.0.4 起才真正生效**） |
| 落库判据 | DUT 侧约 40~60s 周期批量落库，`update_time` 列不写，判断联调结果勿依赖它；仿真器 NCS 的值每秒周期上送，改值后 DUT 库在一个落库周期内跟着变 |
| 设备自动开启（1.0.3 起） | 程序一启动，PLC-仿真、NCS-仿真 这两个服务端通道就自动「开启设备」并开始监听 502 / 2404，不必再手动点；主站-仿真（客户端通道）不自动启动，仍由 `scripts\start.ps1` 启动并开自动读取。`start.ps1` 对已开启的设备再调一次启动是空操作 |
| 「开始」按钮（1.0.2 起） | 按「开始」后：PLC 的 12 个参数点恒为定值（上限 6/15/15/6、下限 0、调节速度 3/4/4/3）；NCS 只有 7 个驱动点（频率 YC502、电压 YC504/YC904、cosφ YC515/615/915/1015）各自小幅正弦起伏（周期 40~89 秒），其余电气量由映射公式实时推出；遥信、遥设不参与。不按「开始」时这些点启动即为基准值（50 / 10.5 / 0.8），不必手写。按「停止」即冻结 |
| 机组有功的跟踪偏差（1.0.3 起） | 机组有功＝派发值限幅在铭牌内，再加一个很小的跟踪偏差（6 MW 机组 ±0.02 MW、15 MW 机组 ±0.045 MW，约 0.3% 额定），所以母线有功（YC222、YC235）也会小幅起伏。偏差借用该机组自己的 cosφ 驱动点，各机组互不相关。派发值在铭牌及以上时只有负向一半（机组不超额定）：6 MW 机组在 5.98~6.00 之间。指令反馈（PLC YC301~307）恒等于命令本身。不按「开始」时偏差为 0 |
| 人工写值的限制 | NCS 的派生点（无功、电流、母线量等）和 4 个功率点、PLC 的 4 个指令反馈点由映射锁定，手写会被拒（提示"请修改驱动点或先停用对应映射"）。要特定值就改驱动点或 PLC 遥设 |
| 浮点 / 负数探针 | 模拟停止时写 `YC502=50.123`（不要用 YC225，它是派生点），DUT 库 `yc502` 应在 40~60s 内变成 50.123，核对后写回 50；负数整型探针写 PLC `YC513=-555`，核对后写回 0 |
| 「模拟配置」对话框 | 保存时未勾选的点会被关闭，主界面「开始」随之空操作，直到重新勾选或整进程重启；打开对话框时按当前启用的点预勾选，不手动取消勾选就不会踩到 |
| config.ini（1.0.4 起真正生效） | 1.0.4 起带不带 BOM 都能读，文件里的每一项都生效：`[server]` 的 `port`、`host`、`open_browser` 改后整进程重启生效。**1.0.3 及以前**包里的 `config.ini` 带 BOM，程序读取报错后整份回退到默认值（默认值与文件内容相同，所以平时看不出），改端口、关自动开浏览器都不起作用 |
| 「单位」列（1.0.4 起） | 三个设备测点表的「真实值」后面多一列「单位」，只对遥测行显示：有功 MW、无功 Mvar、电压 kV、电流 A、频率 Hz、功率因数 —（无量纲）；PLC 的上下限与指令反馈 MW、调节速度 MW/min。单位是库里的数据（`point_yc.unit`），只用于显示，不参与计算和报文 |
| 显示或隐藏「单位」列 | 改 `config.ini` 的 `[server] show_unit_column`（`true` 显示，`false` 隐藏，不写这一行按显示），保存后**刷新浏览器**即生效，仿真器和 DUT 都不用重启 |
| 改单位、添加测点、重新导入点表 | 单位只能用 SQL 改：`tools\sqlite3.exe data\ems.db "UPDATE point_yc SET unit='kV' WHERE code='YCxxx';"`，改后要**整进程重启**才显示（不要用"重新加载设备配置"，见上）。界面上添加测点、或用 Excel 重新导入点表，得到的点单位是空的，重跑 `tools\point-units-20261128.sql` 即可补齐：`tools\sqlite3.exe data\ems.db ".read tools\point-units-20261128.sql"` |
| 复制设备（不可用） | SQLite 包里"复制设备"不可用：接口返回成功但复制 0 个设备，日志报 `unknown function: now()`（上游缺陷：建设备记录时的时间戳默认值是 MySQL 写法，SQLite 不认）。"添加设备"走同一处代码，很可能同样不可用（未实测）。需要新设备时手工创建 |
| start.ps1 与 DUT | **换包或重启之后要重启 DUT 时，用 `scripts\start.ps1 -NoMaster` 起步**：它只起后端并确认 PLC-仿真、NCS-仿真 已监听，不起 主站-仿真，并打印下一步。等 DUT 重启完成（DUT 自己的日志出现 `rtdbManager start`）再跑 `scripts\start-master.ps1`，由它启动主站-仿真、开自动读取（batch，周期 2000 ms）、发总召唤，并确认 DUT 回了报文。`start-master.ps1` 起主站之前先探测 DUT，下面三种情况不起主站，只报错并给出补救办法：2404 端口连不上；端口接受了连接又马上断开；DUT 的端口通、但 DUT 还没连上仿真器（PLC-仿真 上没有客户端连接，确认无碍可加 `-Force`）。顺序见《割接与回滚手册》第四节。不带 `-NoMaster` 的 `scripts\start.ps1` 行为不变：立刻起主站并开自动读取；DUT 不在线时在启动主站那一步报错退出（约 10 秒后），后端和两台服务端设备已经起来，之后手动跑 `tools\ems_local.py start master`、`autoread master`、`gi master` 或 `scripts\start-master.ps1` 即可。2026-11-28 先跑 `start.ps1` 再重启 DUT，仿真器在 DUT 连上来的瞬间崩溃过一次（因果未严格证明，按这个顺序最稳妥）。两个脚本的 Web 端口取自 `config.ini` 的 `[server] port`。2026-11-28 之前组装的包里没有 `-NoMaster` 和 `start-master.ps1`（看 `scripts\` 里有没有 `start-master.ps1`），那种包照旧直接起 exe |
| AGC 派发 | 06 写值是否跟随 ys5 取决于 DUT 的投入条件（远方/就地、闭锁等），与仿真器无关；本期只做链路回归，未验证 AGC 派发 |
| GPL | `source\` 内含全部源码（含全部本地补丁，均带「本地补丁」注释）与许可文本，随包交付，不得闭源外发 |
