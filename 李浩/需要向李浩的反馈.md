## 一、hisdb 建库脚本字符集需修正（重要）

- **现象**：按 `qplantagchisdb_mysql.sql`（2026-11-04，gbk 方案）部署时，程序中文告警（warn_info 列）插入全部失败或乱码。
- **实测根因**（performance_schema 抓帧验证）：程序（Qt4 + MySQL ODBC 8.0）发送的中文是 **UTF-8 字节，并非脚本注释所称的 GBK**；DSN 未配 `Charset` 时 Connector/ODBC 会把连接字符集协商成 latin1 → 中文按 latin1 收 → 转 gbk 列时报 `Incorrect string value`，且写失败会触发"写失败"告警再写再失败的**自激风暴**（曾刷出 312MB 日志）。
- **我方已修复**：DSN 加 `Charset = utf8mb4`；七表 `CONVERT TO utf8mb4`；库默认字符集亦转 utf8mb4（DSN/表/库三层统一）。修复后告警中文落库完好（12 行 HEX 逐字节验证）。
- **请李浩确认/跟进**：
  1. 确认程序侧字符串编码路径（QString → ODBC），确认程序恒发 UTF-8，便于根因闭环；
  2. 今后部署文档、建库脚本统一按 utf8mb4 方案；
  3. 重建 hisdb 请用同目录修正版 **`qplantagchisdb_mysql_utf8mb4.sql`**（表结构与 gbk 版逐字一致，仅字符集不同），勿再使用 gbk 旧版。
